## Non-negotiable research rules
1. **No leakage.** Splits are grouped by baby (or recording/device when baby is unknown).
   No group may appear in more than one fold. Deduplicate audio across datasets by hash
   *before* splitting. Augmentation happens only on training data, after splitting.
2. **Test folds are sacred.** All tuning, early stopping, calibration and threshold choice use
   validation data only. Test predictions are produced once per finalised configuration.
3. **Never invent, round-up, or "estimate" a number.** Every figure that goes into the paper must
   come from `results/paper_numbers.json`, which is generated by `src/report.py` from saved run
   outputs. If a number does not exist yet, leave the placeholder.
4. **Log every run, including failures**, per `docs/RESULTS_SPEC.md`. Never overwrite a run folder.
5. **Change one thing at a time** relative to a named parent run (this is the ablation table).
6. **Fixed seeds** (0,1,2 by default) and 5 grouped folds; report mean ± std.
7. **Primary metric is macro-F1**, not accuracy. Report honestly, including bad results.
8. **Infant audio is sensitive personal data.** Never upload raw audio anywhere public, never
   commit `data/` to git, never send audio to third-party APIs. Released artefacts contain no
   audio unless the source licence allows and Idris approves.

## Session protocol
- Start: read STATUS.md, state the next task, confirm the environment works.
- During: small commits with clear messages; run `pytest -q` for `src/` utilities you change.
- End: update `docs/STATUS.md`, append to `docs/LAB_NOTEBOOK.md`, run `python -m src.report`
  so `results/RESULTS.md` and `results/paper_numbers.json` are current.
- Ask Idris before: spending money on cloud GPUs, emailing anyone, downloading gated data that
  needs him to accept terms, deleting anything in `results/`, or changing the evaluation protocol.
